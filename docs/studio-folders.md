# Папки из Meridian Studio

Studio → **Папки** задаёт названия, порядок, видимость на дуге и распределение
сборок. Настройки хранятся в `DATA_DIR/studio/folders.json`. После изменения
нужно выполнить **Публикация → Подготовить → Опубликовать**. Изменения папок
помечают предыдущую сборку distribution.json как устаревшую.

## Формат distribution.json

Корневые `version`, `servers`, модули и ссылки остаются в прежнем формате.
Добавлено только необязательное расширение:

```json
{
  "version": "1.0.0",
  "servers": [{
    "id": "demo-1.20.4",
    "name": "Demo",
    "version": "1.0.0",
    "minecraftVersion": "1.20.4",
    "address": "example.invalid",
    "modules": []
  }],
  "meridian": {
    "folders": {
      "version": 1,
      "revision": "служебная ревизия Studio",
      "folders": [
        { "id": "стабильный-id-папки", "name": "С друзьями", "visible": true }
      ],
      "assignments": {
        "demo-1.20.4": "стабильный-id-папки"
      }
    }
  }
}
```

`assignments` использует **полный server.id из JSON**, совпадающий с каталогом
сборки Studio (`demo-1.20.4`), а не короткое имя `demo`. Сборки без назначения
остаются без папки. При удалении папки сборки сохраняются. Имена ограничены
60 символами; ID папки сохраняется при переименовании.

Старый Helios читает плоский `servers` и игнорирует расширение. Новый лаунчер
без расширения или с неизвестной версией расширения показывает обычный список.
Папки не меняют установку сборок, пути файлов и подключение к серверам.

## Приоритет пользователя

1. Если локального `packfolders.json` нет, структура берётся из текущего
   distribution.json. Обновления Studio, включая удаление папок, применяются.
2. Первое изменение папок в лаунчере сохраняет **полный локальный снимок**
   с `overridden: true`. С этого момента Studio не заменяет и не дополняет
   пользовательскую структуру. Новые сборки без локального назначения остаются
   без папки. Это намеренно общий приоритет пользователя, а не слияние отдельных
   полей.
3. Существовавшие до интеграции локальные файлы считаются пользовательскими,
   в том числе пустые: удалённые пользователем папки не восстанавливаются.
   Нечитаемый локальный файл также не заменяется серверной структурой.
4. Импортированные игроком локальные сборки не распределяются метаданными Studio.
   Их можно перемещать вручную; такое изменение создаёт локальный снимок.

Обычный кеш distribution.json содержит расширение целиком, поэтому папки
сохраняются при автономной работе. Studio не записывает локальный файл игрока.
В настройках лаунчера показано, откуда взята структура.

## Проверки

- `npm test` в лаунчере: локальные папки, миграция, серверные значения по умолчанию,
  сохранение переопределений, защита локальных сборок и прежний парсер Helios.
- `npm test` в Studio: валидация, сохранение, конфликт ревизий, совместимость
  структуры JSON, обогащение настоящей сборки и отметка устаревшего выпуска.

Выпуск проверяется локально. Публикация в рабочее хранилище выполняется обычным
действием «Опубликовать» в Studio.
