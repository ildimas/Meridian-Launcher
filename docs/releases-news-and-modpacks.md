# Релизы, обновления, новости и сборки серверов

Как выпускать новые версии Meridian, как лаунчер обновляется у игроков, откуда берутся новости и как поставлять свои серверные сборки с готовыми настройками.

## 1. Файлы релиза на GitHub

Релиз собирается GitHub Actions (`.github/workflows/build.yml`) по настройкам из `electron-builder.yml`.

| Файл | Зачем нужен |
|---|---|
| `latest.yml`, `latest-linux.yml`, `latest-mac.yml` | Установленные лаунчеры читают их, чтобы узнать о новой версии. Без них обновления перестанут работать. |
| `*.exe.blockmap` | Позволяет Windows скачивать при обновлении только изменившуюся часть, а не все ~90 МБ. |
| `*.dmg.blockmap` | electron-builder пишет их вместе с `latest-mac.yml` (опция `dmg.writeUpdateInfo`). Если их отключить, пропадёт и `latest-mac.yml`, и пользователи Mac перестанут видеть обновления. |
| `.exe`, `.dmg` (x64 и arm64) | Установщики для Windows и macOS. |
| `.zip` (x64 и arm64) | Из него лаунчер на Mac обновляет сам себя (`app/assets/js/macupdater.js`). Без него Mac вернётся к ручной установке из dmg. |
| `.AppImage`, `.deb`, `.pacman` | Установщики для Linux. Все три обновляются сами: в electron-updater 6.7 есть отдельные модули для deb и pacman. |
| Source code (zip/tar.gz) | GitHub добавляет их к любому релизу всегда, убрать нельзя. |

`.tar.gz` больше не собирается: такая установка не обновляется сама и ничего не даёт сверх AppImage.

## 2. Как выпустить новую версию и как она дойдёт до игроков

1. Поднять `version` в `package.json`, например до `2.3.0`.
2. Запушить в ветку `master`.
3. GitHub Actions соберёт лаунчер для Windows, macOS и Linux, зальёт файлы в черновик релиза `v2.3.0` и опубликует его, только когда соберутся все платформы.

Пуши в `dev` и другие ветки сборку не запускают. Пуш в `master` без смены версии соберёт лаунчер, но ничего не опубликует.

Установленные лаунчеры проверяют обновления при запуске и потом каждые 30 минут. Найдя новую версию, лаунчер показывает окно «Скачать и установить / Позже» (когда ничего не запускается и игра не идёт). «Позже» — спросит снова при следующем запуске. «Скачать и установить» — прогресс загрузки, установка и перезапуск на новой версии; настройки, аккаунты и сборки сохраняются. То же доступно во вкладке «О программе» и по значку на логотипе.

| Платформа | Что происходит |
|---|---|
| Windows, AppImage, deb, pacman | Установка через electron-updater. На Windows без мастера установки; deb и pacman спрашивают пароль администратора. |
| macOS | Без подписи Apple стандартный механизм не работает, поэтому лаунчер сам скачивает zip из релиза, сверяет sha512 и после закрытия подменяет `Meridian.app`. Работает, только если лаунчер лежит в «Программах» (или другой папке, куда можно писать); запущенный из dmg или «Загрузок» предложит скачать dmg и перенести лаунчер в «Программы». |

Предварительные версии (например, `2.3.0-beta.1`) получают только те, у кого включено «Получать предварительные версии» во вкладке «Лаунчер».

## 3. Новости

### Как устроено сейчас

Новости берутся из RSS-ленты, адрес которой лежит в поле `rss` вашего `distribution.json`. Сейчас там демо-лента Helios (`https://helios-files.geekcorner.eu.org/rss.xml`), поэтому в лаунчере видно «Welcome to Helios Launcher!».

Подойдёт любая лента RSS 2.0. Лаунчер берёт из каждой записи:

| Тег | Что показывается |
|---|---|
| `title` | Заголовок |
| `pubDate` | Дата (в формате выбранного языка) |
| `dc:creator` | Автор |
| `content:encoded` | Текст новости в HTML |
| `link` | Ссылка на новость |

Такую ленту даёт, например, блог на WordPress, или её можно генерировать самому.

Игроки видят новости, когда открывают панель «Новости». О новых записях сигнализирует точка на кнопке. Отдельной push-рассылки нет: новость дойдёт при следующем открытии лаунчера.

### Переводы новостей (пока не реализовано)

Сейчас `rss` один, и лента одна на всех. Чтобы новости шли на языке игрока, нужно две вещи:

1. **В лаунчере (небольшая доработка):** сначала запрашивать ленту на языке игрока (`rss.ru.xml`, `rss.de.xml`…), а если её нет, основную.
2. **Отдельный репозиторий новостей:** новости пишутся на русском в Markdown. На каждый пуш GitHub Action переводит их на нужные языки через API перевода (DeepL, Claude и т. п.), собирает `rss.<язык>.xml` и публикует на GitHub Pages.

## 4. Свои серверные сборки в лаунчере

### Как это работает

Список сборок лаунчер берёт из `distribution.json`. Сборка сразу видна в лаунчере, но скачивается только когда игрок нажмёт «СКАЧАТЬ» или «ИГРАТЬ». Это и есть «предустановлена, но не скачана».

### Что сделать

1. **Собрать `distribution.json` в [Nebula](https://github.com/dscalzi/Nebula)**, официальном инструменте Helios. На каждый сервер — своя папка:

   ```
   servers/myserver-1.21.1/
     forgemods/ или fabricmods/   моды (обязательные, необязательные)
     files/                       всё, что нужно положить в папку сборки
   ```

   Nebula посчитает хэши и сгенерирует `distribution.json` со ссылками на ваш хостинг.

2. **Разместить файлы и `distribution.json` на хостинге** (свой сервер, GitHub Pages, S3-хранилище и т. п.) и прописать адрес в `REMOTE_DISTRO_URL` в `app/assets/js/distromanager.js`. Сейчас там ещё демо-сервер Helios.

3. **Настройки, начальный экран, список серверов** — положить в `files/`, они скопируются в папку сборки. Например:

   | Файл | Что это |
   |---|---|
   | `servers.dat` | Список серверов в Minecraft (именно `.dat`, не `servers.txt`) |
   | `config/…` | Конфиги модов, в том числе меню и начальный экран |
   | `options.txt` | Клавиши, графика, язык (см. ограничение ниже) |
   | `resourcepacks/…`, `shaderpacks/…` | Ресурспаки и шейдеры |

   Это уже видно на демо: файл `hi.txt` в вашей сборке Demo-1.19.4 пришёл именно так.

### Ограничение: файлы из `files/` перезаписываются

Перед каждым запуском лаунчер сверяет каждый файл из `files/` по хэшу. Если игрок файл изменил, лаунчер скачает его заново.

- Для `servers.dat` и конфигов модов это даже полезно: они всегда остаются в вашем варианте.
- Для `options.txt` — плохо: при каждом запуске у игрока будут сбрасываться графика и клавиши.

Чтобы отдавать `options.txt` как стартовые настройки, лаунчеру нужен режим «копировать, только если файла ещё нет». Это небольшая доработка проверки файлов (пока не реализовано).

### Не путать с вкладкой «Сборки»

Вкладка «Сборки» в настройках — это другое: там игрок сам импортирует сборки с CurseForge или Modrinth. Ваши серверные сборки приходят из `distribution.json`.
